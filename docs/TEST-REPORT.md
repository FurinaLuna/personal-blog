## 三、过程中发现并修复的问题

### 1. 我的测试脚本在共享库上执行了全局破坏性操作（严重，已修）

`full-check` 首次运行时点击了「清理空标签」按钮 —— 该操作会删除**全站所有 0 引用的标签**，
而演示数据里的 **FastAPI / Vue** 恰好没有被 4 篇演示文章引用，于是真的被删了（标签 7 → 5）。

- **修复**：该按钮改为**只读存在性断言**，不再点击（接口行为由 `tests/test_taxonomy.py` 覆盖）
- **数据恢复**：从测试前的 `VACUUM INTO` 备份中按原 id/slug 恢复这 2 个标签，恢复后 6 张表逐项一致
- **教训**：在共享数据库上，"多测一点"和"破坏数据"往往只隔一次点击

### 2. 备份方式：`cp` 会写出损坏文件（已修）

首次用 `cp backend/blog.db …` 得到的是 **4096 字节**的损坏副本，而主库实际 **163840 字节**。
改用 `VACUUM INTO` 得到一致性快照（163840 字节，6 张表计数逐一校验通过）。

> 这也印证了评估报告里"SQLite 备份不能直接 cp"的说法 —— 而且这次是在真机上验证的。

### 3. 支撑环境问题（非产品缺陷，但会伪装成失败）

| 现象 | 根因 | 处理 |
|---|---|---|
| `curl 127.0.0.1:5173` 返回 502 | Vite 默认只绑 IPv6 `[::1]`，脚本与 curl 走 IPv4 | 显式 `--host 127.0.0.1` 启动（dev 与 preview 都加） |
| `vite build` 挂死 8 分钟 | 之前被中断的构建留下了损坏的 `node_modules/.vite/deps` 缓存 | 清理该缓存后恢复（4.86s） |
| 构建/脚本偶发"白屏" | Vite 冷编译 + 依赖优化 | 测试脚本内加「预热等待应用挂载」，替代固定 sleep |

### 4. 测试脚本自身的 7 处缺陷（均已修，非产品问题）

| 缺陷 | 表现 | 修正 |
|---|---|---|
| `page_size=100` | 接口上限 50，返回 422 → 附件列表拿不到 | 全部改 ≤50 |
| 标签上限用例只补到 9 个 | 第 10 个当然被接受 → 误判"上限失效" | 先数当前数量，补到正好 10 再试第 11 个 |
| 封面用例选中了错误 input | 页面有多个 `file input`，按 `accept` 盲选命中了 Markdown 编辑器的内联图片 input | 锚定「封面图」标题所在容器 |
| 媒体删除按钮定位过宽 | `li,div` 选中外层容器 → 点到别的按钮 | 取"包含文件名且内部有删除按钮"的最小容器 |
| 分页按钮按文案查找 | 可访问名在 `aria-label`（可见文案只有箭头） | 改用 `[aria-label="上一页"]` |
| `history.back()` 后立即读状态 | 执行上下文被销毁 → 返回 undefined | 拆成两步：先触发后退，等页面稳定再读 |
| 正则过度转义 `/rss\\+xml/` | 实际匹配"rss 后跟反斜杠" | 改为 `/rss\+xml/` |

### 5. 一次"疑似产品 bug"的排查（结论：非缺陷）

生产包运行时 B4 报 `403 账号已被停用`。手动复现完整序列（建号 → 提权 → 停用 → 启用 → 降权 → 登录）
**全部正常（200）**，确认后端无缺陷。根因是该用例只设置了 `role`，隐含依赖前序用例留下的 `is_active`
状态 —— 已把前置条件显式化（同时设置 `role` 与 `is_active`），并新增 **A8d 状态落库复核**断言，
避免"响应成功但状态没落库"这类问题继续伪装成权限问题。

## 五、遗留风险与建议

1. **限流在 E2E 期间被临时关闭**（`RATE_LIMIT_ENABLED=false`），测后已恢复默认。已实测恢复后
   连续 8 次错误登录会在第 6 次返回 429 —— 但**评论与点赞的 429 仍无端到端覆盖**（后端单测已覆盖登录限流）。
2. **`清理空标签` 是全局破坏性操作**，管理后台没有二次确认或影响范围提示。建议：点击后先提示
   "将删除 N 个未被引用的标签"，让操作者知道影响面。
3. **`VACUUM INTO` 应固化进备份流程**：目前仓库没有备份脚本，而 `cp` 会写出损坏副本。
   建议加 `make backup-db`（内部用 `VACUUM INTO`）。
4. **Vite 默认绑 IPv6** 会让"用 127.0.0.1 的脚本/工具"连不上。已在本次启动命令里显式 `--host 127.0.0.1`，
   但 `Makefile` 的 `dev-frontend` 仍是 `npm run dev`（默认绑定）。建议在 `vite.config.ts` 里固定
   `server.host = '127.0.0.1'`，让所有入口行为一致。
5. `tools/` 下三个 CDP 脚本各自硬编码了 Chrome 路径（`smoke-check` 有多路径回退，另两个没有）。
   建议后续抽 `tools/lib/chrome.mjs` 统一，但**本次刻意不做**（避免动到已稳定的回归网）。
