## 1. 可扩展的新功能

| # | 做法（一句话） | 预期收益 | 难度 |
|---|---|---|---|
| 1.1 | 编辑器草稿本地自动保存：定时把 `content_md` 快照写 localStorage，重新进入时提示「发现未保存草稿，是否恢复」 | 防误关标签页丢稿，是写作者最痛的丢失场景 | 中 |
| 1.2 | 文章「系列 / 合集」：新增 `series` 字段，详情页顶部显示系列导航（当前 prev/next 只按时间排，连载读起来是断的） | 技术连载的完读率；把「相关文章」从猜变成确定 | 中 |

## 2. UI 与交互美化

| # | 做法 | 预期收益 | 难度 |
|---|---|---|---|
| 2.1 | 标题锚点加 `scroll-margin-top: 6rem`（当前**完全没有**，点目录跳转会被吸顶头部挡住标题） | 目录跳转体验，是当前最实在的一个 UI 缺陷 | 低 |
| 2.2 | 全局 `prefers-reduced-motion` 降级（全库只有 1 处使用 `motion-reduce`） | 前庭敏感用户；也是 Web 无障碍的硬性项 | 低 |
| 2.3 | 暗色下给 `<html>` 加 `color-scheme: dark`，并补 `<meta name="theme-color">` | 滚动条、原生 select/输入框在暗色下不再突兀；移动端地址栏配色跟随 | 低 |
| 2.4 | 触摸目标 36px → 44px（主题切换等 3 处 `h-8 w-8` 图标按钮） | 移动端误触 | 低 |
| 2.5 | 列表入场用 stagger 动画（`animation-delay` 递增），加载态统一走 `LoadingSkeleton` | 首屏编排感；现在卡片是"啪"地整块出现 | 低 |
| 2.6 | 后台表格窄屏卡片化（`<table>` 在 390px 下只能横向滚动） | 手机上能改文章状态 | 中 |
| 2.7 | 空状态统一：所有列表走 `EmptyState`，且给「有筛选无结果」与「一篇都没有」两种文案 | 现在两种语义可能共用一套文案 | 低 |
| 2.8 | 首页 hero 重排：头像 + 站名 + headline + 社交链接做杂志式不对称布局 | 首页辨识度（当前是标准列表流） | 中 |
| 2.9 | 正文排版细节：引用块左侧装饰条、表格斑马纹、脚注样式、中英文混排间距 | 长文可读性 | 低 |

## 5. 推荐执行顺序（投入产出比优先）

### 第一波：半天 ~ 1 天，几乎零风险，都是「补洞」

1. **2.1 标题锚点 `scroll-margin-top`** —— 真实缺陷，用户每次点目录都会遇到
2. **2.3 `color-scheme: dark` + theme-color** —— 3 行改动，暗色质感立刻完整
3. **2.2 `prefers-reduced-motion` 全局降级** —— 无障碍硬性项
4. **2.4 触摸目标 44px** —— 3 处
5. **4.2 静默 catch 补注** + **4.7 全局错误边界** —— 线上排障与白屏兜底
6. **4.9 `/ready` 探针** —— 部署环节顺手补齐

### 第二波：1 ~ 2 天，结构性收益，需要跑全量验证

7. **4.1 `useAction()` 抽象** —— 后台 8 页一起受益，先做这个再做新功能
8. **3.1 路由预取 + 3.3 首屏图片优先级** —— 体感提升最明显的两项
9. **4.3 Vitest 三个关键用例** —— 后续所有 UI 改动的安全网，越早越好
10. **2.6 后台表格移动端卡片化 + 2.7 空状态统一**
11. **3.5 公开 GET 加 ETag**（注意缓存边界，见下）
12. **1.7 标签/归档分页**

### 第三波：3 ~ 7 天，需要设计与迁移

13. **4.5 请求 ID + 结构化日志** → **4.6 限流**（生产化必备，与功能无关但要排在上线前）
14. **1.1 草稿自动保存** —— 写作者高频痛点
15. **1.6 多尺寸 + AVIF**（含老数据兼容）
16. **4.4 服务层拆分**
17. **1.2 系列文章** → **1.4 统计趋势** → **1.5 评论通知**

### 明确建议**暂缓**的

- **1.3 全文检索**：文章不过百时 `LIKE` 完全够用，属于「为想象中的规模付费」
- **1.8 版本历史**：数据模型变更大，收益要等到真的误删那天
- **SSR / 预渲染**：唯一能彻底解决 OG 抓取的方案，但等于重写前台（Astro/Nuxt），成本单独评估

## 6. ⚠️ 可能破坏现有功能的改动（动手前必读）

| 改动 | 风险点 | 规避方式 |
|---|---|---|
| **给公开 GET 加缓存 / ETag** | `/admin/**`、`/auth/me`、写接口一旦被缓存，用户会看到别人或过期的数据；Vite 与 nginx 各有一层 | 只给前台只读接口加；`Cache-Control: no-store` 显式标注后台与鉴权接口；nginx 按 location 分别设置 |
| **拆 `ArticleService`（4.4）** | 154 个测试几乎全打在文章路径上；`/articles/{slug_or_id}` 的数字/字符串双解析、`set_tags` 的异步惰性加载陷阱都在这条链路上 | 只做「搬移」不做「改写」；测试**只增不改**，跑通后再动实现；`git mv` 保持历史 |
| **改路由 / 布局（任何触碰 `router/index.ts` 的改动）** | 历史 bug：`/admin` 父路由同时写 `component` 与 `meta.layout`，导致布局嵌套两层、子页面完全不渲染。单元测试和类型检查**都发现不了** | 改完必须跑 `make smoke`（34 项真实浏览器冒烟）；新增路由时布局只走 meta 一处 |
| **改 `vite.config.ts`（加 Vitest / 改分包）** | `vitest` 与 `vue-tsc`、`@vitejs/plugin-vue` 版本组合易冲突；改 `manualChunks` 可能让 markdown 包被重复打进主包 | 先 `npm run type-check && npm run build` 确认基线体积，改完对比；锁小版本 |
| **图片多尺寸 / AVIF（1.6）** | `Attachment` 表与上传响应字段变化；老文章正文里的封面是硬编码 URL（`/media/...` 相对路径），字段改名会导致 404 | 只增字段不改名；`cover_image` 保持原值，新尺寸放 `variants`；写一次性脚本回填 |
| **动 `style.css` 的 `.prose` 覆盖层** | 全站正文、后台预览、MarkdownEditor 共用一套样式，改一处影响三个地方 | 改动后同时检查：文章详情页、后台编辑器预览、关于页 |
| **上传/存储相关改动** | SVG 已被刻意排除在白名单外（存储型 XSS），别为了"支持 SVG"把它加回来 | 保持白名单；如需 SVG 走独立域名托管 |
| **改 `useHead` 的标题逻辑** | 它与路由 `afterEach` 是「路由标题为底、业务标题为盖」的协作关系；初版曾因卸载时重置而冲掉新页面标题 | 冒烟里 `站点标题` 一项断言 `title.includes('首页')`，正是这个约定守着的 |

> 通用纪律：任何动到路由、布局、样式层、上传链路的改动，收尾必须跑
> `make check`（ruff + 154 测试 + type-check + build）+ `make smoke`（34 项）。
> 这两套曾经抓出过「后台侧边栏渲染两遍」「登录后被弹回登录页」这类只有真实浏览器才暴露的问题。
