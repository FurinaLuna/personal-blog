# 开发日志

本目录收录 personal-blog 项目的逐日开发日志，按 `YYYY-MM-DD.md` 命名。

日志内容：当天做了什么、关键决策（为什么这样做）、验证结果、踩坑备忘、
后续候选。与 `docs/DESIGN.md`（静态方案）互补——DESIGN 回答「系统长什么样」，
日志回答「它是怎么一步步变成这样的」。

## 写作约定

> **每一次改动都必须留下日志，并随改动一起提交推送。**
> 这条是硬约定，不是「有空再写」。

一篇日志至少覆盖四件事：

1. **改了什么**——文件与提交号，能对应到 `git log`；
2. **为什么这么改**——尤其是**放弃的方案**。只写结论的话，半年后看到
   这段代码的人（包括自己）会重新踩一遍已经否决过的路；
3. **怎么验证的**——跑了哪些命令、得到什么数字；实测出来的缺陷要写清
   复现方式（「CDP 连续进两篇文章并滚动」「两次 GET 对比时间戳」）；
4. **踩了什么坑 / 学到什么**——这一节最容易被省，也最值钱。
   凡是「排查了很久才发现」的，都值得写一行：下一个遇到的人可能就是你。

**尤其是 bug**：写清根因，而不是「修了个 bug」。日志里出现「把 bug 说成了
设计取舍」这种自我修正也照写——它比正确的结论更能防住下一次。
