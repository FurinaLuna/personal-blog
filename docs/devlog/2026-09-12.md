## [00:10] - Bug 修复：两个只有真实浏览器才能发现的前端问题

- **文件**: `frontend/src/stores/auth.ts`、`frontend/src/main.ts`、`frontend/src/router/index.ts`
- **Bug 1**：登录后访问后台被弹回登录页。根因是 `restore()` 里
  `if (restoring.value) return` 让并发调用者不等待进行中的恢复，守卫拿到 `user=null`
  就判定未登录（而 `/auth/me` 其实已返回 200）。修复：并发调用方共享同一个 Promise；
  并在 `main.ts` 改为 `router.isReady().then(mount)`，消除「挂载早于守卫」的窗口。
- **Bug 2**：后台侧边栏渲染两遍、子页面完全不显示（列表接口根本没发）。
  根因是 `/admin` 父路由既挂了 `component: AdminLayout` 又声明了 `meta.layout`，
  导致布局被嵌套两层，内层拿不到 slot 内容。修复：父路由不写 component，布局只走 meta。

## [13:20] - 第八批：生产化能力（请求 ID / 结构化日志 / 限流）+ 草稿自动保存（第三波前两项）

### 模块 A：可观测性与限流（后端）

- **`utils/logging.py`**: `JsonFormatter`（单行 JSON，含 ts/level/msg/request_id +
  `extra_fields` 展开）、contextvar 承载请求 ID、`setup_logging()` 幂等且只接管
  `blog` logger（不动 uvicorn 自己的启动/访问日志）
- **`api/middleware.py`**: `RequestContextMiddleware` —— 校验客户端自带
  `X-Request-ID`（正则 + 长度上限，防日志注入）或生成，回写响应头，
  响应后记一条结构化访问日志（method/path/status/duration_ms），
  异常路径也记（否则 500 现场只剩框架默认打印）；探活接口不记以免淹掉真日志
- **错误体统一带 `request_id`**：DomainError / RequestValidationError 两个 handler
- **`utils/ratelimit.py`**: 进程内固定窗口计数器 + 内存上限驱逐（防换 IP 撑爆内存）
- **`api/deps.py`**: `client_ip()` / `client_key()` + `rate_limit()` 依赖工厂；
  配额：登录 5/分、评论 5/分、点赞 20/分；429 带 `Retry-After`
- **配置**: `LOG_JSON` / `LOG_LEVEL` / `TRUST_PROXY_HEADERS` / `RATE_LIMIT_ENABLED`
- **顺带修掉一个真实安全问题**：`comments.py` 原先**盲信 X-Forwarded-For**
  并把伪造 IP 存进库；改为统一走 `client_ip()`，默认不信任、只有开
