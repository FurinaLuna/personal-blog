## [17:15] - 安全三连（`de5be72`）

### Bug 1：`X-Forwarded-For` 取值端取反

- **文件**：`backend/src/app/api/deps.py`、`deploy/nginx.conf`
- **根因**：`client_ip()` 取 XFF 的**最左**一跳，而 nginx 用的是
  `$proxy_add_x_forwarded_for` —— 它是「在客户端传来的值后面**追加** `$remote_addr`」，
  所以最右才是最近一跳可信代理写进去的真实来源，最左由客户端随意伪造。
- **两种配置两种坏法**：
  - 开 `TRUST_PROXY_HEADERS`：`-H 'X-Forwarded-For: 9.9.9.9'` 每次拿到新桶，
    **登录限流 5/分形同不存在**，伪造 IP 还会被当成评论者地址入库；
  - 保持默认 `false`：`request.client.host` 恒为 nginx 容器 IP，**全网共用一个桶**，
    一个脚本就能把所有人的登录与评论锁死，UV 统计恒为 1。
- **修复**：优先取 `X-Real-IP`（nginx 里恒为 `$remote_addr`），否则取 XFF 最右一跳。

### Bug 2：生产启动门禁缺失（`ASSESSMENT.md` 里的 P0，此前未做）

- **根因**：`is_production` 只用来决定要不要关 `/docs`，于是只改了
  `APP_ENV=production` 的实例会带着**写在开源仓库里的 JWT 密钥和管理员口令**
  正常启动并对外服务。
- **修复**：新增 `Settings.check_production_safety()`，**一次性报全**所有问题
  （默认密钥 / 密钥不足 32 字节 / 默认管理员口令 / `DB_AUTO_CREATE` /
  `SEED_DEMO_DATA` / `DEBUG`），由 `create_app()` 在装配最前面强制执行。
- **判断**：密钥一旦公开就不再是秘密，代价不可逆，所以选择「启动失败」
  而不是「打条警告继续跑」——警告在容器日志里没人看，启动失败一定会被处理。

### Bug 3：评论 `author_site` 只校验长度、不校验协议

- **文件**：`schemas/comment.py`、`CommentSection.vue`、`utils/format.ts`
- **根因**：前端把它直接绑到 `:href`，而 **Vue 不清洗动态 href**。
  实测修复前返回 201 并原样入库；全站 token 就存在 localStorage。
- **修复**：后端白名单只放行 http/https，前端加 `safeExternalUrl()` 兜底存量脏数据。

### ⚠️ 我自己第一版修复引入了新漏洞（被自己写的用例抓出）

判断顺序写成了「先无条件补 `https://`，再校验协议」，于是
`javascript:alert(1)` 被补成 `https://javascript:alert(1)` —— 协议项看起来合法，
伪协议反而蒙混过关。**必须先识别自带协议，再决定要不要补全**。
另外空白与控制字符要单独拒绝，防 `java\nscript:` 这类拆分写法
（浏览器解析 URL 时会自行剥掉空白）。

## [17:34] - 前端健壮性与无障碍（`05e2978`）

- **相关文章请求无竞态保护**：正文有 `useAsyncData` 的请求 id 兜底，
  `related` 是裸写的——快速连点两篇时 B 的响应可能后于 C 到达，
  C 的正文下面挂着 B 的推荐。→ 加代次标记，迟到响应直接丢弃。
- **瞬时网络错误被永久缓存成「未登录」**：`restore()` 在任何异常下都置
  `restored = true`，一次网络抖动被记成确定的「没登录」，之后守卫再也不重试。
  → 401 才是确定答案；其余保持 `restored = false` 让下次导航自动重试，
  并对瞬时错误额外重试一次。
- **`http.ts` 缺「续期成功但重放仍 401」的出口**：会出现 token 还在、
  守卫继续放行、但每个请求都 401、页面永远为空且没有出口的状态。
- **主题 store 裸访问 `localStorage` 可能导致整页空白**：它在 `main.ts` 里被
  **立即实例化**，模块求值阶段抛错会让 `router.isReady().then(mount)` 永远不执行。
  → 新增 `utils/storage.ts` 统一探测与兜底（**访问 `localStorage` 这个属性本身**
  就可能抛 `SecurityError`，不只是读写值）。
- **`ConfirmDialog` / `MobileToc` 声明了 `aria-modal` 却没兑现**：
  对话框不移动焦点、Tab 能跑到遮罩背后；移动目录的 `lockScroll(true)` **从没被调用过**。
- **Markdown 编辑器默认模式下每敲一个字跑整条渲染管线**：预览用 `v-show`，
  而 `v-show` 照样渲染子树，computed 是惰性的、节点在就会求值；默认模式恰好是「编辑」。
  → 改 `v-if` 让节点根本不渲染，并给预览加 200ms 防抖。
- **`loadArticle` 只绑 `onMounted`**：`articleId` 变了但实例被复用时，
  表单静静地继续显示上一篇，而保存会 PATCH 到新 id 上——一条链接之遥的数据丢失。
- **13 处表单控件只有 placeholder、没有可访问名称**（placeholder 不是可访问名称）。

## [18:48] - 工程与工具链（`cc0a974`）

### `import-linter` 在 Windows 上必挂

- **根因**：`.importlinter` 的契约名与注释是中文，而 import-linter 用**系统默认编码**
  读它。中文 Windows 默认 GBK，解析阶段直接抛 `UnicodeDecodeError` 并 exit 1 ——
  看起来像「分层契约被破坏了」，实际只是文件读不出来。CI 在 Ubuntu 上正常，
  所以这个坑只坑本地 Windows 开发，而 Makefile 与 README 都明确支持 Windows。
- **修复**：新增 `backend/scripts/lint_imports.py`，检测到未开 UTF-8 模式就用
  子进程以 `-X utf8` 重新拉起自己。
- **两个实现细节都是踩出来的**：
  1. 用 `subprocess` 而不是 `os.execv`——**Windows 上 execv 会丢掉子进程退出码**
     （实测：子进程 `exit(1)`，父 shell 收到 0），而退出码正是这个门禁的全部意义。
  2. `lint_imports()` 是**返回**状态码而不是 `sys.exit`（真正 `sys.exit` 的是它外面的
     click 包装）。第一版直接忽略返回值，等于静默关掉了门禁——
     用「故意破坏契约」的临时工程验证：现在破坏时返回 1、正常时 0。

### 其余四项

- **`IntegrityError` 没有翻译**：项目里到处是「先查重、再插入」，两步之间永远存在
  竞态窗口，输的一方拿到 500。→ 全局 handler 翻译成 409，
  原始异常只进日志（数据库错误会暴露表名与列名）。
- **`visit_logs` 只增不减**：`record()` 每次详情访问写一行，读取只覆盖近 90 天。

  另加站长端点可手动触发并看到删除行数。
- **备份只有手工操作**：`.gitignore` 里有 `blog.db.bak-*`，说明是靠手敲命令。

## [19:05] / [19:16] - 定时发布与全文检索（`3a3a175` / `b38ed22`）

### 定时发布

- **模型选择**：**没有新增 `scheduled` 状态**，而是「`status=published` +
  一个未来的 `published_at`」。可见性判定只需在既有的 `is_publicly_visible`
  一处加时间条件，不必改枚举、不必写迁移，也不会到处都要回答
  「scheduled 到底算不算已发布」。**到点自动可见，没有任何定时任务**。
- **踩坑**：更新路径必须是 `elif` —— 显式传的时间不能被「首次发布补当前时间」
  覆盖掉，写成两个独立 `if` 的话排期会被无声改成「现在」，功能直接失效。
- **前端**：`is_scheduled` 是后端**派生字段**（`computed_field`）。
  后台列表里这类文章的 status 就是 published，不额外标记的话界面显示「已发布」
  而前台搜不到，作者会以为是自己搞错了。

### FTS5 全文检索：分词器选型是成败关键

实测两个候选，**结论与直觉相反**：

| 分词器 | 三字查询「数据层」 | 两字查询「博客」 |
|---|---|---|
| `unicode61`（FTS5 默认） | **0 条**（整段汉字是一个 token） | 0 条 |
| `trigram` | 1 条 ✅ | **0 条**（按三字符滑窗，查询词需 ≥3 字符） |

用 `unicode61` 等于把中文搜索做成「精确全文匹配」，**比原来的 LIKE 还差**。
所以最终是**混合**：≥3 字符走 FTS5（快 + bm25 排序），1–2 字符退回 LIKE。
只上 FTS 会把中文搜索做残，而这类问题在任何英文语料上都测不出来。

**另一个必须处理的现实问题**：`articles_fts` 是 FTS5 **虚拟表**，
`Base.metadata.create_all` 不会创建它（只有跑过迁移才有）。而 README 快速开始走的
正是「自动建表 + 不跑迁移」，不处理的话搜索直接 500（no such table）。
→ 启动时幂等补建 + 搜索前**实际探测**，缺索引就安静退回 LIKE。

**还有一个会误删索引的隐患**：虚拟表数据库里有、`Base.metadata` 里没有，
autogenerate 认为「这个表被删了」——下次 `make migration` 会生成
`DROP TABLE articles_fts`，跑下去就是搜索索引被静默删掉，而且它出现在一个
看起来完全无关的迁移里。→ `alembic/env.py` 加 `include_object` 排除 FTS 表及影子表。

- **验证**：`pytest` **331 / 345 passed**；`alembic upgrade/downgrade` 双向验证，
  触发器增删改同步实测；`smoke` 34/34；CDP 实测搜索页空态、查询进 URL、
  两字中文有结果、无结果走空态、导航有入口。

## [19:30] / [19:32] - 版本历史与修订展示（`3f2a972` / `00e960b`）

- **判断**：这是项目里**唯一一个真正不可替代**的功能。其它问题都能用别的方式凑合，
  只有「误删了一段、改完发现还是上一版好」没法补救。存储成本极低
  （Markdown 纯文本），收益是「敢改」。
- **什么时候产生一版**（本模块唯一需要判断、也最容易做错的事）：
  - 只在标题 / 摘要 / 正文真的变了时快照，改元数据不产生版本；
  - 判定基于「库里当前值 vs 将要写入的值」，而不是「请求里有没有带这个字段」——
    按后者写的话，编辑器每次整段重发都会多出一版完全相同的历史；
  - 快照存**改动前**的样子（存新值的话列表第一条永远等于当前内容，
    用户第一反应是「这不是没变吗」，反而不敢用）；
  - **恢复本身也留一版**——「恢复错了」恰恰是最可能被触发的场景。
- **`list` 接口不返回 `content_md`**：一屏几十版、每版几 KB，全带上会让响应上兆。
- **IDOR 防护**：`/articles/{id}/revisions/{rid}` 必须同时校验两者匹配，
  否则换个自增 id 就能读到全站文章的正文历史。
- **口径比文章详情更严**：历史里可能有作者删掉的内容，属于草稿性质，
  不能跟着「文章已发布」一起放行。
- **顺带**：修掉 `articles_fts` 会被 autogenerate 误删的隐患；
  发现 `articles.series_id` 的外键在库里是**内联未命名**的
  `REFERENCES series(id) ON DELETE SET NULL`（**存量问题**，DDL 证据在 FTS 迁移
  之前的版本上就是这样），autogenerate 会一直想重建它——修它要重建整张
  `articles` 表，风险与收益不成比例，**本次未改，留作单独处理**。
- **`00e960b`**：前台显示「修订于」。阈值 1 天——保存草稿、改错别字这类

## [20:06] - 搜索二次修复（`43a2100`）

用户反馈「搜索感觉不够好」。查下来**比"不够好"更严重**。

### P0-1：分页是坏的

```python
limit = page_params.offset + page_params.limit   # 第 1 页 = page_size
return Page.build(items, len(ids), ...)          # total 被截断成 page_size
```

命中 12 条时显示「找到 5 条」，前端 `total > PAGE_SIZE` 判断为假 →
**翻页控件根本不渲染 → 第 6 条之后永远打不开**。
而当时的注释把这件事写成了设计（「分页控件只需要知道有没有下一页」）——
**把 bug 说成了取舍**。→ 真实 COUNT + LIMIT/OFFSET。

### P0-2：短查询与长查询排序不一致

长查询走 FTS5 + bm25，短查询走 `list_public(sort=LATEST)`，而后者**置顶优先**。
实测：搜「数据」第一篇是只在正文里顺带提了一句的置顶文章，
搜「数据层」第一篇却是标题命中。**同一个搜索框，排序随字数变化。**
→ 两条路径共用同一套语义：命中位置分层 → 层内相关度 → 新文优先，都不看置顶。

### P2：时间衰减 —— 两个坑都是实测出来的

1. **bm25 的量纲随语料规模变化几个数量级**：3 篇语料下稀有词约 -1.0，
   202 篇下约 -8.8，高频词只有 -1e-6。任何固定的加减值都会在某个区间里
   彻底压倒相关度（语料小的时候 +0.5 就等于「完全按时间排」）。
   → 用 `分数 / 年龄因子`（**除法**）。分数是「越小越好」，
   乘以大于 1 的因子反而会让旧文**更靠前**。
2. **档距必须大于最大衰减倍数**：一开始用 -10/-5/-1，而衰减上限是 2.0，
   `-10 / 2.0 = -5` 正好等于摘要档，**六年前的标题命中被降级成了摘要档**。
   → 改成十的幂（-100/-10/-1）。
3. **分层必须放在 bm25 前面**：小语料下 bm25 的 IDF 趋近 0，没有区分力，
   单靠它排序会退化成纯时间序——标题命中反而输给正文命中。

### P1：命中高亮与片段

- 后端补 `snippet`（正文里命中关键词的那一段）。正文命中时标题与摘要可能一个字都没有，
  不给出处用户只能猜「这条为什么会出现」。
- 前端把标题 / 摘要 / 片段按关键词切段，命中部分包 `<mark class="hl">`。
  **刻意不拼 HTML 再 `v-html`**：正文与搜索词都是外部输入，拼 HTML 就多一处
  必须消毒的地方；分段 + 插值天然转义。
- **收敛入口**：首页搜索框改为直接跳 `/search`。它此前是「在列表里筛」，
  与搜索页是两套规则——同一个搜索框在用户眼里就是同一个功能。

- **验证**：`pytest` **370 passed**（+10）；`vitest` **138 passed**（+8）；
  `smoke` 34/34；`interaction` 22/22；API 端到端：total=12、第 3 页仍有 2 条、
  两条路径下标题命中都排在置顶的纯正文命中之前、片段含关键词且为纯文本；
  CDP 实测：首页搜索框跳转、命中处渲染出 `<mark>`、
  搜索词里的 HTML 未被执行（`q=<img src=x onerror=alert(1)>`）。

## 本次会话的学习清单

### 判断与流程

1. **测试要断言「应该怎样」，而不是「现在怎样」。** 我写的
   `test_both_paths_put_title_match_first` 第一版断言的是当时的（错误）行为，
   修好之后它「失败」了——那不是回归，是测试写错了立场。
   反过来，另外两个用例（小语料下 bm25 无区分力、衰减跨档）
   **抓出了我自己设计里的缺陷**，是断言「应该怎样」的直接收益。
2. **区分「缺陷」与「取舍」。** 我把 `total = len(ids)` 写成设计说明，
   实际是 bug。凡是解释里出现「只需要」「足够」这类词，都该再问一遍
   「那反例是什么」。
3. **自己写的修复可能引入新漏洞。** `author_site` 的「先补协议再校验」
   差点让伪协议蒙混过关——是同一批写的用例抓出来的。修完要重新审视
   判断顺序，而不只是看目标用例是否变绿。

### 技术细节

4. **`$proxy_add_x_forwarded_for` 是追加语义**，可信的那一跳在**最右**。
5. **`onupdate` 对 Core `update()` 同样生效**——计数类自增会污染 `updated_at`。
6. **`v-show` 仍会渲染子树**，computed 惰性求值的前提是「节点不存在」。
7. **`useHead` 这类「整体覆盖 head」的 composable，每次调用都是全量写入**，
   同一页面调用两次会互相覆盖。
8. **Vue 不清洗动态 `href`**；`v-html` 之外还有这条注入路径。
9. **`create_all` 不建虚拟表**（FTS5），而 autogenerate 会想把它们删掉——
   需要 `include_object` 护栏。
10. **FTS5 的 `unicode61` 对中文无效**（整段汉字一个 token），
    `trigram` 可用但**要求查询词 ≥3 字符**。
11. **bm25 没有固定量纲**，跨语料规模差几个数量级，不能叠加绝对值；
    且它返回「越小越相关」，衰减要用**除法**。
12. **`os.execv` 在 Windows 上丢子进程退出码**，要转发退出码就用 `subprocess`。
13. **中文 Windows 控制台是 GBK**：脚本输出 emoji 会在最后一句 `print` 上抛
    `UnicodeEncodeError`，**看起来像整个脚本失败了，其实工作已经做完**。
    解决：`sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。

### 环境与工具（本机特有，容易反复踩）

14. **不要用 heredoc 写含反斜杠的代码**——`cat > f <<'EOF'` 会把 `\\` 吃成 `\`。
    本会话因此在两处浪费了轮次（JS 正则、Python 字符串）。
15. **SQL 里内联 `ESCAPE '\'` 会被 f-string 当成转义引号**，
    反斜杠被吞掉后剩下的引号会把后续内容当字符串字面量，
    报 `ESCAPE expression must be a single character`。
    解决：从 `_LIKE_ESCAPE` 常量插值，全程不写转义。
16. **探针脚本里不要重复 URL 编码**——`quote()` 调两次会把 `%` 编成 `%25`，
    表现为「接口返回零结果」，很容易误判成后端 bug。
17. **`netstat` 取 PID 停服务后，Vite 的文件监听会锁住文件**，
    写入报 `ReplaceFileW EIO`；改前端文件前先停 dev server。
